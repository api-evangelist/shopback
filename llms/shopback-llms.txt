## API Reference
- [Getting Started - Tokenized-Payments](https://docs.shopback.com/reference/getting-started-tokenized-payments.md)
- [Account Linking](https://docs.shopback.com/reference/account-linking-1.md)
- [Pre-Auth Requests](https://docs.shopback.com/reference/pre-auth-requests.md)
- [Immediate Charge](https://docs.shopback.com/reference/immediate-charge-1.md)
- [Key Concepts](https://docs.shopback.com/reference/key-concepts.md)
- [Login](https://docs.shopback.com/reference/login.md): There is a clean Login and Logout process associated with the Authentication process. Before you can  Login, you need to obtain credentials from ShopBack - provided after registering a set of valid merchant details.
- [Create order](https://docs.shopback.com/reference/initiateorder.md): This is where you can initiate an order with ShopBack, by using the **initiateOrder** method. We also provide a number of methods to refund orders. For example if the consumer returns one (or all) item(s) of an order, you can initiate a full or partial refund. You would be asked to send us the SKU number of the items to be refunded.
- [Get order status](https://docs.shopback.com/reference/getorderinfo.md)
- [Order refund](https://docs.shopback.com/reference/initiateorderrefund.md)
- [Tokenized-Payments](https://docs.shopback.com/reference/tokenized-payments.md)
- [Initiate a tokenized payment link session](https://docs.shopback.com/reference/initiate-link-session.md): Creates a PENDING link session and returns a `redirectUrl` and `appToken`. The merchant opens `redirectUrl` in an in-app browser and passes `appToken` as `X-ShopBack-App-Token`.
- [Get link session status](https://docs.shopback.com/reference/get-link-session.md): Returns the current state of a tokenized payment link session. Poll this endpoint after redirecting the user to determine when the consent flow is complete.
- [Exchange an auth code for a payment token](https://docs.shopback.com/reference/swap-payment-token.md): Validates the one-time auth code issued after the user completes the ShopBack consent flow and returns a reusable payment token scoped to the merchant channel.
- [Revoke a linked payment token](https://docs.shopback.com/reference/unlink-payment-token.md): Unlinks a payment token for the authenticated merchant channel. Returns 400 if an active pre-auth (AUTHORIZED) is still open for the account.
- [Get cashback balance for a payment token](https://docs.shopback.com/reference/get-cashback-balance.md): Returns the user's available cashback balance for the merchant channel associated with the payment token.
- [Create a pre-authorization](https://docs.shopback.com/reference/create-pre-auth.md): Places a hold on the funds associated with a payment token. Use capture to settle or void to release the hold.
- [Capture a pre-authorization](https://docs.shopback.com/reference/capture-pre-auth.md): Executes the held funds for a pre-authorization and creates an order. The pre-auth must be in AUTHORIZED status.
- [Get a pre-authorization by ID](https://docs.shopback.com/reference/get-pre-auth.md): Returns the current state of a pre-authorization. Use this to poll for status transitions after create, capture, or void operations.
- [Immediate tokenized payment charge (auth + capture)](https://docs.shopback.com/reference/immediate-charge.md): Charges the user's linked payment method in a single step without a pre-authorization hold. Use this for one-shot payments where you do not need to adjust the amount before capture.
- [Void a pre-authorization](https://docs.shopback.com/reference/void-pre-auth.md): Releases the held funds for a pre-authorization. The pre-auth must be in AUTHORIZED status. If the provider rejects the void, the pre-auth stays AUTHORIZED and the merchant may retry.
- [Getting Started](https://docs.shopback.com/reference/in-store-getting-started.md)
- [Authentication](https://docs.shopback.com/reference/getting-started-authentication.md)
- [Generating an HMAC Signature](https://docs.shopback.com/reference/generating-hmac-signature.md)
- [Acknowledge notification](https://docs.shopback.com/reference/notification-1.md): This API is implemented by the payment partner. ShopBack will send the following request parameters to the `webhookUrl` supplied by the payment partner during onboarding.
- [Create order - QR / URL (dynamic)](https://docs.shopback.com/reference/create-dynamic-qr-order.md): Use this endpoint to create an order to accept payment using ShopBack’s dynamic QR code or to accept payments for an in-store context through a customer-facing app or website. This endpoint creates a payment order with the dynamic QR code or relevant URL for redirect.
- [Scan consumer QR](https://docs.shopback.com/reference/scan-consumer-qr.md): Use this endpoint to create an order to initiate payment using ShopBack’s consumer-presented QR code.
- [Get order status](https://docs.shopback.com/reference/get-order-status.md): Use this endpoint to check for the status and details of an order.
- [Order refund](https://docs.shopback.com/reference/order-refund.md): Use this endpoint to refund captured orders with ShopBack.
- [Cancel order](https://docs.shopback.com/reference/cancel-order.md): Use this endpoint to cancel a payment before processing. Cancellations are not allowed once a customer has swiped-to-pay on ShopBack’s mobile application.
